# AutoClicker

<p align="center">
  <img src="assets/autoclicker-logo.png" alt="AutoClicker — логотип" width="220">
</p>

**AutoClicker** — компактный высокоскоростной автокликер для Windows 10/11 x64, написанный на Rust. Он отправляет синтетические клики левой или правой кнопкой мыши и управляется из небольшого окна либо глобальной клавишей **F6**.

> Режим «Максимум» не задаёт фиксированную частоту: приложение непрерывно отправляет события клика так быстро, как позволяет Windows и принимающее приложение. Из-за этого одно ядро процессора может быть загружено почти на 100%.

## Общие сведения

- **Платформа:** Windows 10/11, 64-bit.
- **Язык и зависимости:** Rust, системный Win32 API; сторонних Rust-крейтов нет.
- **Тип приложения:** нативное графическое Windows-приложение, без консольного окна.
- **Кнопка мыши:** левая или правая.
- **Управление:** кнопка в окне и глобальный переключатель F6.
- **Режимы скорости:** «Максимум» и заданная частота от 1 до 100 000 кликов в секунду.
- **Передача ввода:** `SendInput` из Windows `user32.dll`; драйверы, службы, сеть и доступ к файлам пользователя для кликов не используются.

Значение 100 000 CPS в поле — верхняя граница настройки, а не обещание, что Windows или конкретная программа обработает столько кликов. Реальная скорость зависит от ОС, планировщика, оборудования и целевого приложения.

## Как это работает

1. Нажатие **F6** или кнопки «Запустить» создаёт отдельный рабочий поток. Повторное нажатие останавливает его.
2. Поток формирует последовательности «кнопка нажата → кнопка отпущена» и передаёт их Windows через `SendInput`.
3. В режиме **«Максимум»** поток не спит и не вводит искусственную задержку: он отправляет небольшие пакеты по 16 кликов за вызов Win32 API. Пакетирование уменьшает накладные расходы на вызовы API, а проверка состояния между пакетами сохраняет быструю остановку.
4. В режиме **«Своя частота»** используется монотонный таймер. Вблизи запланированного времени применяется короткое активное ожидание для точности; при отставании программа пропускает просроченные интервалы, а не создаёт догоняющую очередь кликов.
5. Счётчик показывает пары событий, принятые Windows API. Это не подтверждает, что целевое приложение обработало каждое событие.

Windows ограничивает доставку синтетического ввода. В частности, процесс с обычными правами не может гарантированно отправлять ввод в приложение, запущенное с более высокими правами. Не запускайте автокликер от администратора без необходимости.

## Использование

1. Распакуйте архив релиза целиком — рядом с `AutoClicker.exe` должна находиться папка `assets`.
2. Запустите `AutoClicker.exe`.
3. Выберите режим скорости и кнопку мыши. Для заданной частоты укажите целое число от **1** до **100000** кликов/с.
4. Нажмите **«Запустить (F6)»**. Курсор останется на текущем месте; клики направляются в окно, которое принимает ввод в данный момент.
5. Нажмите **F6** ещё раз или кнопку **«Остановить (F6)»**, чтобы остановиться.

F6 регистрируется как глобальная горячая клавиша. Если её уже использует другое приложение, автокликер сообщит об этом; в таком случае используйте кнопку в окне. Не все программы принимают синтетические клики, а некоторые игры, сайты и сервисы запрещают автоматизацию — соблюдайте их правила.

## Сборка и тесты

Нужен стабильный Rust toolchain. Для сборки именно Windows-версии используйте Windows с установленными компонентами **Visual Studio Build Tools** (MSVC и Windows SDK):

```powershell
rustup target add x86_64-pc-windows-msvc
cargo test
cargo build --release --target x86_64-pc-windows-msvc
```

Сборка оптимизирована для скорости и размера: включены оптимизация release, LTO, один codegen unit и удаление символов отладки. Для проверки логики частоты запустите `cargo test`.

Чтобы собрать папку приложения и ZIP-архив для распространения:

```powershell
.\scripts\package-windows.ps1
```

Результат появится в `dist/`:

- `dist/AutoClicker-windows-x64/AutoClicker.exe` и необходимые рядом файлы;
- `dist/AutoClicker-windows-x64.zip` — готовый архив для пользователя.

При создании тега вида `v*` GitHub Actions собирает Windows x64 и публикует ZIP как артефакт GitHub Release. Ручной запуск workflow также создаёт архив как Actions artifact.

## Ограничения и ответственное использование

- «Максимум» может заметно нагружать CPU; остановка доступна через F6 и кнопку в окне.
- Предельная фактическая скорость задаётся Windows и приложением-получателем и может быть существенно ниже выбранного значения.
- `SendInput` может быть ограничен уровнем целевого процесса, политиками безопасности или самим приложением.
- Используйте автоматизацию только там, где она разрешена. Не применяйте её для обхода ограничений, спама или нарушения правил игр и онлайн-сервисов.
